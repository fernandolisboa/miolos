## Traps

**Turbo's cache for `packages/db` tests does not cover `apps/api/src`.** Run `pnpm test --force` before trusting a green gate after an `apps/api` change. **Dependabot npm PRs cannot be merged as opened** (no lockfile change). Land one hand-made bump, outside `minimumReleaseAge` (7 days). **A perfect day needs a lineup buffered before midnight (ADR-0087).** The buffer alert exists to prevent that. **Seven per-game medals is T-CORE-S70's maximum** and `termoGuessWins` is at its floor: an eighth game needs a quota decision first (ADR-0138). **Content is not a Turbo test input:** after editing `content/crossword/lexicon.tsv`, `content/termo/answers.csv` or `content/termo/reserve.txt`, run `generate:crossword`, `generate:termo` and `pnpm test --force`. Re-curation moves a published answer to `reserve.txt`, never deletes it (ADR-0114).

**A property test with no explicit timeout can go red on a slow CI runner.** Campo Minado's engine tests rode the 5000 ms default until #423's gate timed one out; they now carry ADR-0055 timeouts. A new generator test over 2000 ms on the gate gets its own timeout in the same PR.

**Never roll either app back past #330 part 3 once a 7×7 day exists** (ADR-0117): the old API answers a 49-cell completion 400 and sync drops it for good. Stop 7×7 with a forward PR that generates at 5. Before about 2026-10-22, check both production deployments are on the merge commit. Likewise a Rainhas record with `autoCrossed` fails the pre-#326 schema: sync pending completions before rolling `apps/web` back past #326. A pre-#368 client's `strictObject` rejects a Sudoku record that has `notes`, so an in-progress board with notes looks missing there and is overwritten on a rollback; solved records never carry notes. The same holds for `mistakes` (#369): a pre-#369 client rejects an open record that has it; closed records never carry it.

**Once a Campo Minado row exists, never roll `apps/api` or `apps/web` back past #389 PR 2:** an old api answers every Campo Minado completion 400 and sync drops it for good. Stop the daily with a forward PR instead (out of `DAY_GAMES` and the cron's `COST_ASCENDING_GAMES`).
