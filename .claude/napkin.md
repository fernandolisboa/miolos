3. **[2026-08-15] A vitest timeout sized off an ISOLATED local run under-shoots CI by 4-9x — and the ">10s locally" trigger excludes every test that actually flakes**
   Do instead: anchor on the highest **measured** figure — CI where one exists, worst **contended** local otherwise, **never a single-file run** — then ×4, rounded up to the next 5s, arithmetic in a comment beside the test. Trigger: over **40%** of the applicable budget (2s of `testTimeout` 5s, 4s of `hookTimeout` 10s; the hook half is unswept except PGlite's `createTestDb`, instrumented at #114 behind `MIOLOS_TEST_DB_TIMING=1`). **A bare local `pnpm test` is CAPPED at turbo concurrency 2 (#114), so it is never a "contended" anchor** — the uncapped command is `pnpm test --force --concurrency=10`, green on the 16 GB / 8-core box with #120's worker bound and a legal local anchor again, but **CI gate logs stay the preferred source**; no eligible anchor → record that as the reason the budget is not re-derived. Samples from a worker configuration nothing ships (pre-#120 `apps/web` at `cpus − 1`) are history, not anchors (ADR-0055 (o)); a capped run under-shoots CI and `turbo run test`. **Never size from a run in which anything timed out**: a killed test reports the wall, so that run's max is censored and turbo's sibling-kill biases the rest low. The anchor is a sample max, not a bound — a later session exceeding it is the estimator working, so **say so in the comment**: a recorded max owes an update only when a sample crosses the **trigger**, never on every new gate row, and a bare "max = N" goes stale on the next push (#109's own gate moved `T-WEB-S43` 944 → 990 ms mid-review; the next row came back at 666). Where a whole file shares one cost driver, budget the **file** (`vi.setConfig`), not whichever test runs first. **RTL's `waitFor` carries its OWN 1000 ms default, invisible to every rule above** — `vi.setConfig`'s `testTimeout` does not reach it, so an unbudgeted `waitFor` around a background dynamic import is a wall-clock budget on module RESOLUTION and flakes under contention: `conclusion-lazy.test.tsx`'s `T-WEB-S289` nonogram arm failed **alone** (1338/1339, 96/97 files) on #163's first CI gate — an archive PR touching nothing in `src/play/**`, `src/nonogram/**` or the conclusion graph — and passed on a re-run that was a real execution (`cache miss, executing …`), not a replay. Read a lone red there as contention, confirm with the re-run's cache-miss line, and give the `waitFor` an explicit CI-anchored budget **in the ticket that OWNS the test** (#145), never in the unrelated PR whose gate happened to surface it: retuning it there makes that PR the place a future bisect lands. **The same shape recurred at #64 without a `waitFor` in sight, so read the rule as being about REAL-TIMER WALL-CLOCK ASSUMPTIONS generally, not about `waitFor`:** `play-sync.test.ts`'s *"stops flushing once it has been torn down"* failed **alone** (1364/1365) on a PR that touches neither `src/play/sync.ts` nor that suite, and passed on the re-run and on every local run before and since. An implicit margin is still a budget; it is just one nobody wrote down. Same diagnosis, same cure, same ownership rule: re-run once, and if it recurs, fix it **in the ticket that owns the test** (fake timers, as its own sibling at the ladder test already uses) rather than in whatever PR the gate happened to surface it under. Ceiling, not target: over `budget / 2` diagnose and record, **never raise on the tripwire alone** — only a budget decision 2 never derived whose trigger fires is *set* (ADR-0055 (p)); `/ 2` not `/ 4`, since `budget = anchor × 4` makes `/ 4` the anchor. Full record: ADR-0055 (j)–(p) (#109, plan 051).

9. **[2026-08-14] CI runs on `pull_request` ONLY — "CI green on main post-merge" no longer exists as handoff evidence, and PR runs auto-cancel on a new push**
   Do instead: cite the PR's own `gate` run (the ruleset-required context) as the merge evidence; never re-add `push: [main]` to buy back a signal the ruleset already enforces pre-merge. A `gate` showing "cancelled" means a newer commit superseded it, NOT a failure — read the newest run. `.github/workflows/impeccable.yml` is deliberately left un-keyed: its `deployment_status` ref is a raw commit SHA (Vercel sets `deployment.ref` to the 40-char SHA), so concurrency there would buy nothing and could let the miolos-api event cancel the in-flight miolos-web scan. Corollary for caching: Actions caches are branch-scoped and nothing writes main's scope any more, so every PR's FIRST `gate` run is cold and warmth only accrues across pushes to the same PR — don't read a cold first run as a cache bug. **And a CONFLICTING PR produces no `pull_request` run at all** (#113, step 7): when a sibling merges to main and the branch goes `mergeStateStatus: DIRTY`, GitHub cannot build the merge ref, so pushing produces `Impeccable` (which fires on `deployment_status`) and **silently no `gate`** — an absent required context, not a failed one. Diagnose a missing `gate` with `gh pr view <n> --json mergeable,mergeStateStatus` BEFORE re-pushing; the fix is `git merge origin/main`, and the gate runs on the first try after it. **A DIFFERENT failure has the same smell and a different cure: a `gate` that EXISTS and sits `QUEUED` forever** (53 min with nothing else running, #67) is a stuck run on GitHub's side — `gh api …/runs/<id>/cancel` answers **HTTP 500** and `gh run rerun` says *"already running"*, so neither escape works. **Close and reopen the PR**: `reopened` is a default `pull_request` trigger type, a fresh run picks up immediately, and no empty commit pollutes the history. Never read a long queue as a red.

Same family as § Execution 1's presence-vs-correctness and #64's range-assertion lesson. **[2026-08-22, #149] The CONVERSE, which is what to do with a mutation that survives: some guards are UNBINDABLE, not untested, and only the mutation tells the two apart.** #149's reviewer ran five; three were caught and two were not, and both survivors are undetectable in principle — under **React 18+ a `setState` on an unmounted component is a silent no-op**, so a hook that drops its `cancelled` flag is observationally identical to one that keeps it, and the four `.catch` arms are unreachable because every shipped client is total. Run the mutation, then CLASSIFY the survivors — *untested* is a finding to fix, *unbindable* is a finding to state. **[2026-08-27, #205] Two sharpenings, ten review rounds each half. (a) An ATTRIBUTION is a claim about a test, and only the mutation settles it:** a comment sweep attributed the hydration gate in eight play-screen roots to five test ids and **four of the eight were ungated** — `T-WEB-S94` looked like Termo's record and is a `PlaySkeleton` composition suite whose only `TermoScreen` arm asserts *after* `act()`, so it never sees the first paint. ## Parallel-Stream Orchestration
1. **[2026-08-22] Only ADR numbers still need cross-stream reservation — the docs/ NNN sequence and its README row are gone (ADR-0074)**

   Do instead: one stream owns the canonical file; siblings byte-copy and later sync via merge-from-main; serialize merges (owner first) and have every fix/merge agent `git merge origin/main` before gates.
3. **[2026-07-31] ADR-0023 floors main validity/determinism properties at ≥100 fast-check runs, pinned seeds in test files (never a vitest.config.ts in packages/games)**
   Do instead: cite ADR-0023 in engine test plans; secondary/achievability properties may sample lower (Binairo P3=25 precedent).
4. **[2026-07-31] Engine API conventions (post-#46/#47/#48): options-object generate({seed, weekday}), GAME_-prefixed exports, typed RejectionReason unions, diagnosed validator result, typed RangeError via isWeekday in generate**
   Do instead: converge new game modules on the Binairo/Sudoku shapes on main; validators return verdicts (Nonogram style) — cross-engine harmonization of throw-vs-verdict validators is an open note.
5. **[2026-08-27] A review agent running `pnpm test` OWNS the checkout for the whole round, and a worktree is not the way out**
   A correctness round is 20-50 minutes of mutation runs and full-suite runs in the working tree; editing anything under it invalidates its evidence, so the next tranche cannot start. Do instead: **prepare the next sweep in `/tmp`** — copy the target files out, transform them there, and measure by importing `count`/`density` directly against the scratch paths (both take any path with the right extension) — then apply it in one `cp` when the round lands. Two tranches were fully written and verified this way while reviews ran. Do **not** reach for a git worktree to get a second checkout: § Shell & Command Reliability 8 is what that cost, and a worktree also cannot run `pnpm test` without its own install.
6. **[2026-08-18] A sub-agent's work survives only if it is on DISK — a report that exists solely as a composed final message dies with the process**
   Do instead: every spawned agent whose output is worth more than a minute (explore, plan review, each step-6 lens, verification) writes its report to a file under a session directory OUTSIDE the repo (`~/miolos-session/<issue>-step<n>-<lens>.md`) as its **first** substantive act, and returns a pointer plus a summary. Two of #109's four step-6 reviews died to credit exhaustion after writing their files and **nothing was lost**; a five-agent batch earlier the same session was killed by a process restart and lost everything, because they had only composed messages. `/tmp` does not survive a WSL reboot — the directory goes under `~`. The orchestrator reads the files, never the transcript. **[2026-08-22, #104] BUT two subagent types cannot obey this instruction at all: `Explore` and `Plan` are READ-ONLY** — no Write, no Edit, no shell redirection — so a brief telling them to write their report to disk produces a complete report in a final message and no file. Both happened in one session: a 200-line code map and a complete step-2 plan came back as chat messages only, and the orchestrator had to re-persist each by hand before it could spawn anything else. Do instead: for anything whose output must survive, spawn `general-purpose` (or `claude`); reserve `Explore`/`Plan` for work you will consume immediately in the same turn, and **persist their reports yourself the moment they land** rather than assuming the brief was followed.

8. **[2026-08-21] Agent scratch belongs OUTSIDE the repo, but a TOOL or a PLAN left there is one `rm -rf` from gone — promote it the day it earns reuse**
   Sub-agents write their output to a scratch dir (handoff 058 §6.4) so a dead agent's work survives; that is right and stays. What went wrong is that nothing ever promoted the durable items out. A 34 GB-of-files cleanup of `~/miolos-session/` nearly destroyed a complete Tier 2 plan for an OPEN issue whose own header said "to be committed as `docs/plans/066-…`" (rescued, now committed), and DID destroy `gate-lock.sh` — which two committed skills still invoked, so deleting it silently broke `just-do-it` and `small-fix`. Do instead: scratch holds only re-derivable things (logs, screenshots, diffs, fixtures, superseded review rounds — that is where the megabytes are, not in the docs). The moment a file is a **tool**, it goes into the repo under `scripts/` in that session, not "later". A **plan for an open issue** no longer goes into the repo at all (ADR-0074) — it goes onto the issue as a comment, which is durable in the same way and is where the next session will look for it.
