## Decisions

**D1 — Delivery seam: an optional field on the `/day` per-game claim** (`dayGameStateSchema`, the ADR-0065 decision 2 `hintsUsed` template verbatim). Reasons: post-completion **by construction** — the claim is a projection of the user's own completion rows, so the name cannot exist on a claim before the server judged the day; it survives reload and reaches a second device for free through the seam every conclusion already reads (`useServerDayClaim`); zero new endpoints; the deploy-skew story is already written (strict schema → old client fails `safeParse` → degrades to local projection → recovers on the next fetch). It satisfies ADR-0033 decision 5's own shape: an *authenticated post-completion server read* (`GET /day` is credentialed and parameterless — decision 5 asked for a read, not a route). Rejected: **the completions response** — ADR-0033's Rejected entry is still true in code (breaks the ADR-0028 offline finish, discarded by `acceptResponse`/`settle` before any reload, structurally nameless on the replay path which returns before the wall read), and repairing it means widening the play-record schema; rejected: **a new post-completion endpoint** — a whole route, CORS, contract and credentialed GET (ADR-0051 decision 3's trigger is sized against that count) for one string, and its sole advantage (a `?date=`) buys nothing because the archive is a non-goal (D3).

**D2 — Wire key: `motifName`.** ADR-0033 decision 4's own preferred route: a payload that needs a name *renames its field*. `FORBIDDEN_DAILY_KEYS` is untouched — `"name"`, `"motifId"`, `"mirrored"` stay banned; every existing key scan keeps passing on merit. No forbidden bundle marker is a substring of `motifName`. Rejected: `name` + list amendment — spends a generic standing ban to gain nothing.

**D3 — Render sites in this PR: (1) the in-place conclusion on `/nonogram`, (2) `/nonogram/concluido`.** The cross-device remote completed view is **out** — see D15. **Non-goals, recorded:** the **archive** (`/day` takes no date by ADR-0060's design; the late-result panel composes no reveal at all) and **free play**, which stays unnamed: motifs recur across infinite generated puzzles, a motif name is not an answer that burns, and keeping it unnamed lets ADR-0046 consequence 1 / ADR-0047's "to generate and never to name" survive with a narrowing annotation instead of a reversal.

**D4 — The tripwire is KEPT, with a rewritten warrant.** Wire delivery puts no motif name into any built chunk: `apps/web/scripts/route-client-js.mjs` greps `.next/static/chunks/**/*.js` only (`CHUNKS`, `:194`), and an API JSON response is never a chunk. So the daily-scope grep remains a fully armed tree-shaking check on `@miolos/games/nonogram` (one careless client import still puts 184 names in daily chunks; the grep is the only instrument that sees webpack hoisting). Non-vacuity survives in both directions — `EXPECTED_DAILY_SCOPE`'s malformed-clues control still proves the walk reaches `packages/games` chunks, `EXPECTED_FREE_PLAY_SCOPE` still proves the ADR-0047 attribution separates the two sets. What dies is only its *premise sentence*: the warrant becomes "no motif name may reach daily-scope chunks; the daily name arrives over an authenticated wire, never from the bundle." Markers, scopes and `bundle-markers.test.ts` unchanged. Rejected: retiring it — discarding a live guard because we were licensed to. **This call contradicts Fernando's "replace or retire" instruction and therefore goes in the PR body as a one-line decision point, not only in the step-8 issue comment** (S10): *"#64 keeps the bundle grep instead of spending it — wire delivery leaves it fully armed, and only bundling the motif tables would kill it. Keep (recommended) / retire anyway?"*

**D5 — Record shape: ADR-0070, superseding ADR-0033 in part.** This adds a wire surface and a new publication rule — a decision-level replacement of part of decision 1, not a sentence narrowing — so `docs/agents/domain.md`'s form is `**Supersedes in part:**` (ADR-0067/0041 is the repo precedent). ADR-0033 keeps `Accepted`, gains the reciprocal header and in-place annotations. All other touched ADRs get lettered in-place annotations (ledger below). Rejected: amending 0033 in place only — a new rule of this weight is an ADR (CLAUDE.md).

**D6 — Conclusion shape: `ConclusionPicture` gains optional `name` AND `lead`** (`apps/web/src/play/types.ts`), on the `ConclusionAnswer {result, lead, canonical}` precedent (`types.ts:191-198`). `ConclusionView` renders what it is handed and **imports no nonogram message**. Keeps ADR-0034 consequence (c)'s one-payoff-member-per-game budget — no second member. Rejected: `name` alone — the "Você revelou"-class lead would then have to come from a `messages.games.nonogram.reveal.*` import inside the game-blind shared module, which its own TSDoc (`conclusion-view.tsx:503-509`) and `messages.ts:1227-1234` both forbid. Rejected: a new per-game prop à la Termo's `answer` — crosses the member budget for no gain.

**D7 — A11y: the `<svg role="img">` keeps its role; its `aria-label` composes the name when known; a visible caption carries the lead + the name; NO live-region change.** The conclusion's `role="status"` announcer is a prop composed before mount under the DISJOINT-WRITERS rule (ADR-0042 decision 10 / ADR-0054 decision 4, restated at `conclusion-view.tsx:355-363`) — mutating it when a name lands late would violate that rule, and a caption appearing is not a status. This discharges ADR-0033 consequence (a). **Named residual (ADR-0070):** when the claim lands late (offline finish, then sync) the **accessible name of an already-mounted `<svg role="img">` changes**. That is not a live-region write and is legal, but a post-mount accessible-name mutation is an AT pitfall and is recorded as such, pinned by T-WEB test (3).

**D8 — Freshness at the payoff moment: the day-truth store refreshes when a completion settles `recorded`.** Without it the just-solved player waits for the 60 s poll or a refocus. The refresh is honest independent of #64 — the server's day truth genuinely changed. Trigger site per D12. Import shape preserves ADR-0060 consequence (d)'s single-importer rule (`src/day/**` imported by `src/play/day-state.ts` and nothing else, `T-WEB-S244`): `day-truth.ts` exports `refreshDayTruth()`, `play/day-state.ts` re-exports it as `refreshServerDay()`. One-shot, event-driven — not an interval, so ADR-0060 decision 5's poll annotation is untouched. Rejected: accepting up-to-60 s latency on the feature's whole point.

**D9 — Degraded label: the composed description stays.** Offline finish, pre-sync render, deploy skew, or a killed daily row all render today's exact behavior (`messages.games.nonogram.reveal.aria`, no caption). The name is progressive enhancement; nothing is fabricated (the `RemoteShippedStamp` per-line idiom). ADR-0028's offline requirement is untouched.

**D10 — The name is never persisted into the play record.** The read repeats via `/day` on every mount; the record schema is closed and stays closed.

**D11 — Schema detail:** `motifName: z.string().min(1).optional()` on `dayGameStateSchema`, plus a third `.refine` (value only on `status === "completed"`, message `"motifName is published only on a completed game"`). No `.max`: a read-side cap would invent a constraint no writer enforces. **The `.min(1)` is safe only because of D13** — see there. Wire-legal on any game's claim, *produced* only for nonogram — the Termo-suppression precedent: producer-side rules live in `dayGamesFromRows`. **Named residual for ADR-0070:** `dayResponseSchema.shape.games` maps all four games to the same `dayGameStateSchema` (`contracts/day.ts:60-66`), so `motifName` is wire-legal on termo, sudoku and binairo claims too. Declined alternative, recorded: a `superRefine` on `dayResponseSchema.games` scoping `motifName` to `games.nonogram` — costs a whole-object refine and buys a schema-level guarantee the producer already gives.

**D12 — The refresh trigger lives in `apps/web/src/play/conclusion-view.tsx`, NOT in `sync.ts`.** Verified against the real module graph: `apps/web/test/archive-day.test.tsx:320-358` walks the archive routes' module graph and asserts `graph.filter(p => p.includes("/src/play/day-state"))` and `graph.filter(p => p.includes("/src/day/"))` are both `[]`, plus a `not.toContain("useDayTruth")` string scan over every file in it. `sync.ts` **is** in that graph (`use-play-lifecycle.ts:30` imports `flushPendingCompletions`/`startCompletionSync` from `./sync`, and the companion "the walker is not vacuous" test asserts the archive graph reaches that lifecycle), so `sync.ts → day-state.ts` would red three assertions and — worse — fire a credentialed `GET /day` on an **archive late write** from a public, crawler-facing route, falsifying ADR-0053 decision 9 and ADR-0060 consequence (d). `conclusion-view.tsx` is on that same test's **forbidden** list, so it can never be in the archive graph and adds no edge; it already imports `useServerDayClaim` from `./day-state` (`:28`) and `startCompletionSync` from `./sync` (`:31`), already computes `const syncOutcome = stored?.syncOutcome` (`:182`), and already runs a `useEffect` in the same component (`:155`). Fire `refreshServerDay()` from a `useEffect` **keyed on `syncOutcome === "recorded"`** — never a dep-less effect, which would loop on its own re-render. Rejected: **inverting with an `onRecorded(listener)` registry in `sync.ts`** — it also keeps the graph clean, but it adds a module-level listener set, a registration lifecycle and a second way for the play layer to talk to the day layer, for a trigger one existing effect already expresses. **Consistency with D16/B7 (stated explicitly, because the two fixes interact):** what lands in `conclusion-view.tsx` is a game-blind *trigger* — no nonogram import, no nonogram copy, no per-game branch. The nonogram copy travels the other way, as data on `ConclusionPicture` (D6/D16). The two resolutions do not collide.

**D13 — The empty name is normalised at the wall read, and downstream guards on truthiness.** `packages/core/src/contracts/daily-content.ts:77-82` is `nonogramRevealSchema = z.strictObject({ motifId: z.string(), name: z.string(), … })` — **no `.min(1)`**. `validateNonogram`'s `reveal-name-empty` rejection lives in `packages/games` at *generation* time, not on the read path, so the stored-content schema accepts `name: ""`. Left alone, one such row would return `""`, pass a `name !== undefined` guard, attach `motifName: ""`, and **fail `.min(1)` inside the route's own `dayResponseSchema.parse`** → blanket `catch` → **500 for the whole `/day` payload** (hub, four tiles, every completed view) — verbatim the failure ADR-0065 decision 2 records for the `hintsUsed` cap, and explore landmine 2. So: `getPublishedNonogramMotifName` returns `undefined` for a missing, killed, unparseable **or empty/whitespace-only** name, in one place inside the wall; the route guards `if (name)`. Rejected: tightening `nonogramRevealSchema.name` to `.min(1)` — a write-side content-schema change that can drain the buffer, out of #64's scope.

**D14 — The helper is exported from `@miolos/db/publishing`, never the root entry.** `/publishing` is the dangerous entry (ADR-0024), holds `getPublishedDailyWithSolution`, and has the `listUsedTermoAnswers` precedent for a read-back of stored `content`. Cost, budgeted here because it is red-on-merge otherwise: three surface tripwires in `packages/db/test/published.test.ts` widen **in place, in the same commit as the export** — **T-DB-9a** (`:1055-1071`, the `published.ts` module's exact 8-name list → 9), **T-DB-9c** (`:1098-1114`, the publishing entry's exact 10-name list → 11) and **T-DB-S5** (`:1126-1233`, the union across all four subpaths, `toHaveLength(48)` → **49**, plus the "#64 moves it by exactly one, on the PUBLISHING entry" paragraph in the shape every prior ticket used). **T-DB-9b** (root) and **T-DB-9d** are untouched, which is the proof the name went to the right surface.

**D15 — The cross-device remote completed view is NOT named in this PR.** "Você revelou: Âncora" with **no picture**, on a device where the user did nothing, is a caption for a missing image. ADR-0065 decision 1's honest-absence table is exactly the instrument for this: the picture's absence row stands, and the *name*'s absence joins it as a second recorded absence rather than a fabricated composition. Cutting it also removes the "where does the remote view's lead live" question (`messages.conclusion.remote.*` vs a new optional prop) entirely. Rejected: shipping it because the seam delivers the field for free and "a claim field the remote view silently ignores is a smell" — that is the weakest argument available, and an unread optional field is what the honest-absence table is *for*. Recorded on the issue and in ADR-0070 as an in-scope choice, so a later ticket can reverse it cheaply.

**D16 — All nonogram copy is composed in `apps/web/src/nonogram/nonogram-conclusion.tsx` and handed down as data.** `conclusion-view.tsx:503-509` states the rule about itself — *"This is the ONLY per-game JSX branch permitted in this module; a fifth game adds a claim field, never an arm"* — and the shipped discipline is Termo's `answer` prop (`:364-383`), where `ConclusionView` renders `answer.lead`/`answer.canonical` and never imports `messages.games.termo.*`. `messages.ts:1227-1234` states the sibling rule for `games.nonogram.reveal`. **D17 — Copy register: the lead is impersonal, the second person lives in the aria.** The slot D6 borrows is Termo's `dayWordRow`, where `result` is second-person (*"Você acertou em 4 de 6 tentativas."*) and `lead` is the 11px tracked-uppercase **impersonal kicker** (*"A palavra de hoje era"*, `messages.ts:1085`).
