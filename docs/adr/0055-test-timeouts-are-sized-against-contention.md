## Context

Root `pnpm test` is `turbo run test` at turbo's default concurrency of 10, so all six package suites start at once, each running `vitest run` at `maxWorkers = max(cpus - 1, 1)`. Five tests were riding vitest's undeclared 5000 ms `testTimeout` default under that fan-out and going red on green code — roughly half of all root runs on an 8-core box across three measurement sessions ([#107](https://github.com/fernandolisboa/miolos/issues/107)). Three of the five are the ESLint wall suites, which each pay a one-time flat-config load inside their first `it`; the other two are the exposed Binairo properties, which pay a generator cost. On the last green gate run the worst of them, `T-LINT-1`, sat at **83.7 %** of the default with 814 ms of margin.

The standard that should have prevented this — the napkin's *"size in-file test timeouts at local wall time × 4 with margin; any test >10 s locally gets an explicit timeout"* — is falsified in both halves. Its baseline reads naturally as an **isolated** single-file run, and for these five tests isolated → CI runs materially above ×4, so ×4-on-isolated produces a budget below the figure CI already measures. Its trigger, phrased in isolated seconds, excludes every test that actually flakes: the worst of the five costs well under a second isolated. A trigger phrased in isolated seconds cannot see a contention problem.

Two standing constraints bind anything decided here, and neither is re-opened:

- **ADR-0017** forbids a `vitest.config.ts` in `packages/games` — importing `vitest/config` pulls vite's `.d.ts` (which references `@types/node`) into the package's `types: []` program and silently defeats the purity typecheck backstop. Timeouts there are in-file, which is where all six of the package's existing ones already live.
- **ADR-0023** floors the main validity and determinism properties at `numRuns` ≥ 100. **Run counts are never reduced to buy time**, and #107 ships both Binairo run counts byte-identical.

## Decision

1. **The 5000 ms default is not a budget.** Any test whose **contended local or measured CI** time exceeds **40 %** of the applicable budget — its own explicit timeout where it has one, vitest's default where it does not (2000 ms against the 5000 ms `testTimeout`, 4000 ms against the 10000 ms `hookTimeout`) — carries an explicit in-file timeout, with the arithmetic and both measured figures in a comment beside it. Below the trigger, no timeout. *(**Widened at #114** — [ADR-0057](./0057-the-test-suites-memory-model-and-a-cap-that-binds-locally.md): **where N sites share a single shipped cost driver, the arithmetic and the measured figures live ONCE, beside that driver, and each site points at it BY SYMBOL** — by the module's published subpath where the pointer crosses a package boundary, since most of them do. The number itself still lives at every site; only the arithmetic moves. **The warrant is measured rot, not analogy.** Handoff 048 §4's durable finding is that a document's claims about itself and its neighbours rot faster than its claims about code, and the PGlite population is that finding instantiated: across a **26-file** population, **21** carried a copy of one boot-cost sentence and those 21 had drifted into **nine byte-distinct texts across four attribution families, three of them wrong about the cost they describe**, after being carried forward through four tickets — while the remaining **five** sites carried no arithmetic at all, which is the same rule failing in the other direction. That is a measured rot rate on a comment this decision's own rule would have kept duplicating. It is deliberately **not** derived from decision 3: decision 3's subject is where the *number* lives and its warrant is per-test ordering instability, neither of which applies here. What does apply is decision 4's own observation that *"the cost driver is whatever the timeout is actually budgeting, which is frequently not the test file"* — here it is literally one function in one file. Census: `docs/plans/049-issue-114-plan-the-fan-out-cap-and-the-pglite-hook.md` §4.)* The rule was **swept before it shipped, on the `testTimeout` axis** (gate run [`31888933252`](https://github.com/fernandolisboa/miolos/actions/runs/31888933252), 28 tests over 2000 ms): **seven hits — five fixed by #107, two residual.** The **`hookTimeout` axis is unswept**, because vitest prints no hook durations in any reporter; no hook in this repo has a measured cost, including the ~20 `apps/api` `beforeAll(…, 30_000)` PGlite boots. *(**Narrowed and corrected at #114** — [ADR-0057](./0057-the-test-suites-memory-model-and-a-cap-that-binds-locally.md) decision 4. 2. **The anchor is the highest measured figure, CI first, worst contended local second — and it is a sample maximum, not a bound.** An isolated single-file run is **never** the anchor. A figure from a run in which **anything** timed out is never the anchor either: that run's *sample maximum* is right-censored at the wall, because a killed test reports the wall, and turbo's termination of sibling tasks on first failure means the figures that did complete were taken under **less** contention than a full run's. **Where several tests share one cost driver and their per-test ordering is unstable between measurement sessions, they are one population and every member takes the population maximum** — on #107 the ordering reversed twice, so the wall trio takes one number and the Binairo pair takes one number. Multiplier **×4, one multiplier for both provenances**, rounded up to the next 5000 ms. "Contended" means: the whole suite via `pnpm test --force` at turbo's default fan-out, **no other build or test run on the box — an agent session is expected, and is counted as part of the contention rather than excluded from it** — at least three runs, take the max, **pooled with every earlier session's samples for the same test**. *(**Rewritten at #114**, which is the rewrite the "root fan-out" Consequence below said a cap would owe — [ADR-0057](./0057-the-test-suites-memory-model-and-a-cap-that-binds-locally.md) decisions 2 and 3. **"Contended" still means the whole suite at turbo's DEFAULT fan-out, and a bare `pnpm test` no longer produces it**: the root script caps turbo at 2, so a bare root run is never an anchor for anything. Three consequences, and the third is the uncomfortable one.*

   *First, **the CI gate log is the practical anchor source**. The gate runs `MIOLOS_TEST_DB_TIMING=1 pnpm test --concurrency=10` — uncapped, instrumented, and green throughout — which is the CI-first figure this decision already prefers, now available for the hook axis as well as the test axis.*

   *Second, **locally the uncapped command is `pnpm test --force --concurrency=10`**, and the cap is overridable precisely so that command exists.*

   *Third, **that command is currently red on the reference box** — one green in sixteen pooled runs across two sessions and two trees — and this decision says a run in which anything timed out is never an anchor. **So the local procedure yields no legal anchor at all** until the PGlite class is closed rather than avoided. Where a population has no eligible anchor, **that is recorded as the reason a shipped budget is not re-derived**, and never worked around by using an ineligible figure. It is a live constraint: #109's third residual is defined on the local axis, which no CI sweep can see. Figures: `docs/plans/049-issue-114-plan-the-fan-out-cap-and-the-pglite-hook.md` §2.* *(**Superseded at #109, and the record was owed earlier** — [plan 051](../plans/051-issue-109-plan-the-three-timeout-residuals.md) §3 D7, §6.2; annotation (k).    ***And the corollary that binds every budget sized after #114: a budget sized against CAPPED figures under-shoots the worlds that are still uncapped*** — the CI gate, a developer invoking `turbo run test` directly, and any future revert of the cap. A capped figure may be used to show a shipped ceiling is not breached under the shipped local configuration; that is a different question from sizing, and must be labelled as one.)* The stricter condition *"nothing else running"* is never realised in this repo's workflow (every pre-commit run has an agent session resident) and stating it that way would make the procedure unrunnable-as-written and therefore quietly ignored; it also matters more than it sounds, because on #107 the same wall test measured **3420 ms** under one session's idle definition and **11 733 ms** with only an agent alongside — a 3.4× spread, larger than the multiplier itself, and part of what the ×4 exists to absorb. **The residual, stated as part of the decision:** the anchor is the maximum of a sample drawn from a heavy-tailed scheduling distribution, so it grows with the sample and a later session may exceed it — #107's own anchor moved 4983 → 7907 → 9832 ms across three sessions. The ×4 and the round-up exist to absorb that; the rule is *"anchor on the largest figure measured so far, then multiply"*, never *"the largest figure measured so far is the worst case"*. **`×4` is retained for continuity with roughly 25 shipped in-file timeouts and the napkin's standing constant — it is not derived**, and a future ticket that derives a real multiplier from paired data supersedes it by measurement.

3. **Where a whole file shares one cost driver, the budget is file-scoped, not pinned to a test.** The three ESLint wall suites pay a one-time flat-config load in whichever test runs first, and which test that is moves with load and with any edit to the file — three measurement sessions disagreed about which one it was. So: `vi.setConfig({ testTimeout })` at module scope, and per-`it` only where costs genuinely differ (Binairo `P1` and `P2` each get one; `P3` deliberately gets none, and the comments say why). File scope is safe because vitest's forks pool with `isolate: true` gives every test file its own child process — verified with a PID-pinned probe, not assumed.

4. **A timeout is a ceiling, not a target.** A test over **`budget / 2`** is a defect to investigate and record, never a number to raise, and never an automatic re-derivation either — decision 2's residual means a single figure over the line may be a draw rather than drift, so it is diagnosed and written down before anything moves. Raising a shipped timeout requires fresh measured figures in the PR body and an updated arithmetic comment. *(**Which of decision 2 and decision 4 governs a shipped ceiling — answered at #109** ([plan 051](../plans/051-issue-109-plan-the-three-timeout-residuals.md) §3 D1), as ADR-0057 decision 5 asked the settling ticket to say; annotation (p). **Stated as a partition, so that no shipped ceiling falls between the two decisions.** **Decision 2 governs a budget being SET**: for the first time, or a shipped budget decision 2 never derived on which decision 1's trigger fires — decision 1 requires a conformant budget there and none exists, so one is set, with decision 4's diagnosis written first where the tripwire is also crossed (#109's `P1` and `P3` ramp). **Decision 4 governs every other shipped ceiling** — whether or not decision 1's trigger fires, and whether or not decision 2 derived it.    **Why `budget / 2`, derived rather than picked.** Decision 2 sets `budget = anchor × 4`, so **`budget / 4` *is* the anchor** — a tripwire there fires precisely when a session sets a new sample maximum, which decision 2 predicts as the estimator working normally rather than as a defect. Stated at `/ 4` the two decisions contradict each other by construction, and they were: on #107 itself an independent eight-run block on unchanged code crossed the `/ 4` line four times (11 733, 10 578, 10 510, 10 138 ms against a 10 000 ms line) while every run stayed green. **`budget / 2` is twice the anchor** — a figure there is double anything the pooled sample has ever produced, which is a drift signal and not a draw. The threshold is stated as a fraction of the budget and never as a millisecond figure, because the millisecond figure changes with every budget.

   **The rule, in general form:** **a pull request that touches a timed test's cost driver re-reads that test's CI duration out of its own gate log and into its PR body**, and treats a figure over `budget / 2` as a defect to diagnose and record. ## Rejected

- **`testTimeout` in `apps/web/vitest.config.ts`.** One line, and it would cover all three wall suites at once — but its blast radius is 75 files and 1102 tests. Every unrelated `apps/web` test would take 40 s to report a genuine hang instead of 5 s, forever, for nothing. That is the gate weakening `CLAUDE.md` forbids; the file-scoped form buys the same latency cost for exactly the 57 tests that need it. It also cannot reach `packages/games` at all, where ADR-0017 forbids the analogous fix, and it records no arithmetic anywhere near a test.
- **A CLI `--testTimeout` in each package's `test` script.** Satisfies ADR-0017 literally, but `package.json` is JSON and carries no comments, so the arithmetic would have nowhere to live — and it applies to a whole package, reproducing the blast-radius problem one package over.
- **`describe(name, { timeout }, fn)` on every top-level describe.** Reuses two shipped shapes, but `eslint-db-wall.test.ts` alone has five top-level describes (seven across the trio) and a sixth added later would silently drop back to 5000 ms. It remains the correct shape if a future vitest release changes the isolation default decision 3 rests on.
- **A `beforeAll` warm-up that moves the flat-config load out of the first `it`.** It trades a 5000 ms `testTimeout` for vitest's 10000 ms `hookTimeout` — against a pooled maximum of 9832 ms that is 168 ms of headroom, and the hook axis is the one nothing in this repo can measure. It also does nothing for Binairo, which is half the failing population. Still a legitimate *performance* idea; it is not a timeout fix.
- **Reducing any `numRuns` to buy time.** Forbidden by ADR-0023, not merely discouraged.
