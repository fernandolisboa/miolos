# ADR-0055 — Test timeouts are sized against contention

**Status:** Proposed — 2026-08-15 (issue #107)

## Context

Root `pnpm test` is `turbo run test` at turbo's default concurrency of 10, so all six package suites start at once, each running `vitest run` at `maxWorkers = max(cpus - 1, 1)`. Five tests were riding vitest's undeclared 5000 ms `testTimeout` default under that fan-out and going red on green code — roughly half of all root runs on an 8-core box across three measurement sessions ([#107](https://github.com/fernandolisboa/miolos/issues/107)). Three of the five are the ESLint wall suites, which each pay a one-time flat-config load inside their first `it`; the other two are the exposed Binairo properties, which pay a generator cost. On the last green gate run the worst of them, `T-LINT-1`, sat at **83.7 %** of the default with 814 ms of margin.

The standard that should have prevented this — the napkin's *"size in-file test timeouts at local wall time × 4 with margin; any test >10 s locally gets an explicit timeout"* — is falsified in both halves. Its baseline reads naturally as an **isolated** single-file run, and for these five tests isolated → CI runs materially above ×4, so ×4-on-isolated produces a budget below the figure CI already measures. Its trigger, phrased in isolated seconds, excludes every test that actually flakes: the worst of the five costs well under a second isolated. A trigger phrased in isolated seconds cannot see a contention problem.

Two standing constraints bind anything decided here, and neither is re-opened:

- **ADR-0017** forbids a `vitest.config.ts` in `packages/games` — importing `vitest/config` pulls vite's `.d.ts` (which references `@types/node`) into the package's `types: []` program and silently defeats the purity typecheck backstop. Timeouts there are in-file, which is where all six of the package's existing ones already live.
- **ADR-0023** floors the main validity and determinism properties at `numRuns` ≥ 100. **Run counts are never reduced to buy time**, and #107 ships both Binairo run counts byte-identical.

## Decision

1. **The 5000 ms default is not a budget.** Any test whose **contended local or measured CI** time exceeds **40 %** of the applicable budget — its own explicit timeout where it has one, vitest's default where it does not (2000 ms against the 5000 ms `testTimeout`, 4000 ms against the 10000 ms `hookTimeout`) — carries an explicit in-file timeout, with the arithmetic and both measured figures in a comment beside it. Below the trigger, no timeout. The rule was **swept before it shipped, on the `testTimeout` axis** (gate run [`31888933252`](https://github.com/fernandolisboa/miolos/actions/runs/31888933252), 28 tests over 2000 ms): **seven hits — five fixed by #107, two residual.** The **`hookTimeout` axis is unswept**, because vitest prints no hook durations in any reporter; no hook in this repo has a measured cost, including the ~20 `apps/api` `beforeAll(…, 30_000)` PGlite boots. A third residual, `apps/web/test/nonogram-screen.test.tsx:406`, was found by hand on the local axis, which the CI sweep also cannot see. **Three residuals in total — two from the sweep, one not — all filed as [#109](https://github.com/fernandolisboa/miolos/issues/109).**

2. **The anchor is the highest measured figure, CI first, worst contended local second — and it is a sample maximum, not a bound.** An isolated single-file run is **never** the anchor. A figure from a run in which **anything** timed out is never the anchor either: that run's *sample maximum* is right-censored at the wall, because a killed test reports the wall, and turbo's termination of sibling tasks on first failure means the figures that did complete were taken under **less** contention than a full run's. **Where several tests share one cost driver and their per-test ordering is unstable between measurement sessions, they are one population and every member takes the population maximum** — on #107 the ordering reversed twice, so the wall trio takes one number and the Binairo pair takes one number. Multiplier **×4, one multiplier for both provenances**, rounded up to the next 5000 ms. "Contended" means: the whole suite via `pnpm test --force` at turbo's default fan-out, **no other build or test run on the box — an agent session is expected, and is counted as part of the contention rather than excluded from it** — at least three runs, take the max, **pooled with every earlier session's samples for the same test**. The stricter condition *"nothing else running"* is never realised in this repo's workflow (every pre-commit run has an agent session resident) and stating it that way would make the procedure unrunnable-as-written and therefore quietly ignored; it also matters more than it sounds, because on #107 the same wall test measured **3420 ms** under one session's idle definition and **11 733 ms** with only an agent alongside — a 3.4× spread, larger than the multiplier itself, and part of what the ×4 exists to absorb. **The residual, stated as part of the decision:** the anchor is the maximum of a sample drawn from a heavy-tailed scheduling distribution, so it grows with the sample and a later session may exceed it — #107's own anchor moved 4983 → 7907 → 9832 ms across three sessions. The ×4 and the round-up exist to absorb that; the rule is *"anchor on the largest figure measured so far, then multiply"*, never *"the largest figure measured so far is the worst case"*. **`×4` is retained for continuity with roughly 25 shipped in-file timeouts and the napkin's standing constant — it is not derived**, and a future ticket that derives a real multiplier from paired data supersedes it by measurement.

3. **Where a whole file shares one cost driver, the budget is file-scoped, not pinned to a test.** The three ESLint wall suites pay a one-time flat-config load in whichever test runs first, and which test that is moves with load and with any edit to the file — three measurement sessions disagreed about which one it was. So: `vi.setConfig({ testTimeout })` at module scope, and per-`it` only where costs genuinely differ (Binairo `P1` and `P2` each get one; `P3` deliberately gets none, and the comments say why). File scope is safe because vitest's forks pool with `isolate: true` gives every test file its own child process — verified with a PID-pinned probe, not assumed.

4. **A timeout is a ceiling, not a target.** A test over **`budget / 2`** is a defect to investigate and record, never a number to raise, and never an automatic re-derivation either — decision 2's residual means a single figure over the line may be a draw rather than drift, so it is diagnosed and written down before anything moves. Raising a shipped timeout requires fresh measured figures in the PR body and an updated arithmetic comment.

   **Why `budget / 2`, derived rather than picked.** Decision 2 sets `budget = anchor × 4`, so **`budget / 4` *is* the anchor** — a tripwire there fires precisely when a session sets a new sample maximum, which decision 2 predicts as the estimator working normally rather than as a defect. Stated at `/ 4` the two decisions contradict each other by construction, and they were: on #107 itself an independent eight-run block on unchanged code crossed the `/ 4` line four times (11 733, 10 578, 10 510, 10 138 ms against a 10 000 ms line) while every run stayed green. **`budget / 2` is twice the anchor** — a figure there is double anything the pooled sample has ever produced, which is a drift signal and not a draw. The threshold is stated as a fraction of the budget and never as a millisecond figure, because the millisecond figure changes with every budget.

   **The rule, in general form:** **a pull request that touches a timed test's cost driver re-reads that test's CI duration out of its own gate log and into its PR body**, and treats a figure over `budget / 2` as a defect to diagnose and record. The cost driver is whatever the timeout is actually budgeting, which is frequently *not* the test file — which is why the list has to be written per timeout rather than assumed. **#107's instantiation**, and it is an instantiation rather than the rule: the three ESLint wall suites (`apps/web/test/eslint-{db,free-play,og}-wall.test.ts`); `eslint.config.mjs`; `packages/games/test/binairo/generate.test.ts`; **`packages/games/src/binairo/**`**; or the **version of `eslint`, `eslint-config-next` or `typescript-eslint`** in the root `package.json` or lockfile. The last two are on the list because they are where drift actually originates and neither of them touches the first three; `.github/dependabot.yml` declares `github-actions` only, so those bumps arrive hand-written with no automation to catch them. **Every timeout this ADR causes to be added later owes the same list for its own cost drivers, named in the PR that adds it** — starting with [#109](https://github.com/fernandolisboa/miolos/issues/109)'s three, which #107 files without fixing. [#106](https://github.com/fernandolisboa/miolos/issues/106) is the first pull request to owe the re-read.

## Rejected

- **`testTimeout` in `apps/web/vitest.config.ts`.** One line, and it would cover all three wall suites at once — but its blast radius is 75 files and 1102 tests. Every unrelated `apps/web` test would take 40 s to report a genuine hang instead of 5 s, forever, for nothing. That is the gate weakening `CLAUDE.md` forbids; the file-scoped form buys the same latency cost for exactly the 57 tests that need it. It also cannot reach `packages/games` at all, where ADR-0017 forbids the analogous fix, and it records no arithmetic anywhere near a test.
- **A CLI `--testTimeout` in each package's `test` script.** Satisfies ADR-0017 literally, but `package.json` is JSON and carries no comments, so the arithmetic would have nowhere to live — and it applies to a whole package, reproducing the blast-radius problem one package over.
- **`describe(name, { timeout }, fn)` on every top-level describe.** Reuses two shipped shapes, but `eslint-db-wall.test.ts` alone has five top-level describes (seven across the trio) and a sixth added later would silently drop back to 5000 ms. It remains the correct shape if a future vitest release changes the isolation default decision 3 rests on.
- **A `beforeAll` warm-up that moves the flat-config load out of the first `it`.** It trades a 5000 ms `testTimeout` for vitest's 10000 ms `hookTimeout` — against a pooled maximum of 9832 ms that is 168 ms of headroom, and the hook axis is the one nothing in this repo can measure. It also does nothing for Binairo, which is half the failing population. Still a legitimate *performance* idea; it is not a timeout fix.
- **Reducing any `numRuns` to buy time.** Forbidden by ADR-0023, not merely discouraged.

## Consequences

- **A red root `pnpm test` is a finding again.** `TURBO_CONCURRENCY=1` stops being a standing pre-commit workaround and "re-run until green" stops being an available move. This largely restates `CLAUDE.md`'s evidence rule and is recorded as an effect, not a new rule. It covers the `testTimeout` class: any `Test timed out in Nms` in the five named tests, any assertion failure anywhere, and any red in a package a change did not touch. It does **not** cover the PGlite `beforeAll` class, which is a `hookTimeout` failure this decision never measured, nor turbo's `[ELIFECYCLE]` sibling-termination noise, which is not a test failure at all.
- **The root fan-out is deliberately left uncapped.** `"test": "turbo run test"` is unchanged, so ADR-0017's *"Turbo fans out `pnpm test`"* stays true as written, pre-commit and CI stay identical, and the contention the budgets were sized against remains the contention they actually meet. **[#110](https://github.com/fernandolisboa/miolos/issues/110)** owns the cap and owes this ADR a fifth decision if it ships — including a rewrite of decision 2's "contended" procedure, which a cap invalidates by making the prescribed measurement produce smaller figures.
- **A slow drift inside the budget is invisible until it crosses `budget / 2` on a pull request that happens to touch one of decision 4's five triggers.** No mechanical checker detects growth; decision 4's procedure is a human obligation, and this is the honest residual.
- **The measurements do not live here.** The per-package durations, the isolated → CI factor range, the shipped budgets' arithmetic and the corpus sweep's per-test table are in #107's pull-request body and in `docs/plans/042-issue-107-plan-test-timeouts.md` §2.2–2.3, which are point-in-time records. An ADR carrying a measurements appendix is the fastest-rotting document in the repo, and the factor range in particular has now been measured three times and come out three different ways. **What this ADR keeps is the qualitative finding it rests on: isolated → CI runs materially above ×4 for these tests, so ×4-on-isolated under-shoots.** Decision 1's sweep counts stay, because there the sweep *is* the warrant for the rule; decision 4's threshold is stated as `budget / 2` and never as a millisecond figure, because the millisecond figure changes with every budget.
- **ADR-0017 and ADR-0023 are cited and obeyed, and neither is amended.** Both of the statements this ADR leans on remain true as written, so no reciprocal `**Amended by:**` header is owed — that idiom binds when a record's statement is made *false*, and it is not. Saying so explicitly is deliberate: clearing a record as untouched and being wrong is the failure this repo has now counted seven times.
